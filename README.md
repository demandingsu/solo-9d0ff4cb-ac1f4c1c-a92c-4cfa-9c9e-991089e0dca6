# 夜班接驳车末班核定

给夜班通勤协调员用的 Web 工具：输入时刻表首页 URL、上车站、下车站、最早出门与
到岗截止的日期时间，自动翻页抓取两站时刻表，按**车次号 + 停站顺序**配对，
只保留“发车不早于出门、到站不晚于截止”的班次，给出**发车最晚的一班**及两站来源。

## 功能要点

- **分页抓取**：从首页的站点链接（`a.station-link`）找到两站第 1 页，沿
  `a.next-page` 逐页抓取，直到没有下一页（50 页上限、循环链接保护）。
- **配对规则**：两站记录车次号相同，且上车站停站顺序早于下车站才视为同一行程。
- **服务日区分**：按车次**始发服务日**标注工作日（周一至周五）/ 周末（周六周日）/
  每日；查询时按时间窗覆盖的每个始发日分别判断是否运行。
- **24:xx 跨日时刻**：`24:25`、`25:10` 等按“始发服务日零点 + 时间差”换算为真实
  日期时间；若下车站时刻（如 `01:00`）早于上车站发车（如 `23:50`）且未用 24 小时
  制书写，自动按次日处理。
- **异常提示**：
  - 任一分页抓取失败 / 表头缺列 / 链接循环 → 提示“无法核定末班”，且不展示不可信结论；
  - 车次缺停站顺序、缺关键时刻、两站服务日标注不一致、下车站无该车次记录 →
    逐条告警；若仍有其他完整班次，正常给出末班，告警与答案同时展示。
- 结果页展示末班车次、服务日类型、两站实际到发时间与原始时刻、两站来源 URL，
  以及时间窗内全部可选班次。

## 目录结构

```
.
├── app/                  # 末班核定 Flask 应用（端口 5000）
│   ├── commuter/
│   │   ├── times.py      # 纯逻辑：时刻解析、服务日、配对核定（可单测）
│   │   ├── scraper.py    # requests + BeautifulSoup 分页抓取
│   │   ├── app.py        # Flask 路由与表单校验
│   │   └── templates/index.html
│   ├── tests/            # 18 个单元 / 端到端冒烟测试
│   ├── Dockerfile
│   └── requirements.txt
├── example-site/         # 本地示例时刻网站（端口 5001）
│   ├── app.py            # 含分页、24:xx 跨日、工作日/周末、缺记录与 500 故障站
│   ├── Dockerfile
│   └── requirements.txt
└── docker-compose.yml
```

## 用 Docker Compose 启动（推荐）

```bash
docker compose up --build
```

- 示例时刻网站：<http://localhost:5001/>
- 末班核定应用：<http://localhost:8000/>

在核定页面填写：

| 字段 | 示例值 |
| --- | --- |
| 时刻表首页 URL | `http://example-site:5001/`（容器间用服务名访问） |
| 上车站 | `滨河园区` |
| 下车站 | `中央厂区` |
| 最早出门 | `2026-11-11 22:00` |
| 到岗截止 | `2026-11-12 02:00` |

> 从宿主机浏览器直接访问示例站点时用 `http://localhost:5001/`；
> 但核定应用运行在容器内，抓取 URL 必须填容器网络可达的
> `http://example-site:5001/`。

## 本地直接运行（不用 Docker）

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r app/requirements.txt

# 终端 1：示例时刻网站
cd example-site && python app.py            # http://localhost:5001

# 终端 2：核定应用
cd app && flask --app commuter.app run      # http://localhost:5000
```

此时首页 URL 填 `http://127.0.0.1:5001/`（或 `http://localhost:5001/`）。

## 试一下异常场景

- **缺记录**：示例数据里 N206 在「中央厂区」没有停站记录，任意
  滨河园区→中央厂区查询都会看到黄色数据告警，末班仍由 N205 等完整数据核定。
- **分页失败**：上车站填「故障北站」，其第 2 页返回 HTTP 500，页面显示红色
  “无法核定末班”，并标明失败的分页地址。
- **周末 vs 工作日**：把时间窗放到周六晚上（如 2026-11-14 22:00 至
  2026-11-15 02:00），结果中只会出现“每日”和“周末”班次。

## 适配真实时刻表站点

抓取器对页面结构的约定（见 `app/commuter/scraper.py`）：

1. 首页上站点链接带 `class="station-link"`，文本为站点名；
2. 站点页有 `<table>`，表头包含 车次号 / 停站顺序 / 站点 / 时刻 / 服务日
   （支持常见别名，如“站序”“班车”“到时”等，见 `_HEADER_ALIASES`）；
3. 翻页链接带 `class="next-page"`；
4. 服务日列出现“工作日/平日/weekday”“周末/双休/weekend”“每日/daily”等字样。

结构不同的站点只需调整 `scraper.py` 中的选择器与表头别名，核心核定逻辑
（`times.py`）无需改动。
